# Wiki Schema

> The constitution of this wiki. The LLM reads this before every operation. Customize freely — git tracks the evolution.

## Architecture

```
wiki/
├── _schema.md          # this file
├── _log.md             # operation log
├── _index.json         # generated by scripts/wiki_index.py
├── overview.md         # human-readable index (also generated)
├── rules.md            # validated rules
├── false-beliefs.md    # refuted conventional wisdom
├── inbox-digest.md     # recent ingest summary
├── raw/                # immutable original materials
│   ├── articles/
│   ├── books/
│   ├── papers/
│   ├── podcasts/
│   └── conversations/
├── sources/            # compiled summaries (one .md per source)
├── entities/           # things you track (companies, people, books, projects)
│   └── {NAME}/
│       ├── profile.md  # main page (judgment, related network)
│       ├── tracker.md  # evolving evidence
│       ├── notes.md    # dated research notes
│       └── ... (optional: news.md, model.md, etc.)
├── concepts/           # themes, frameworks, ideas
│   └── {THEME}.md      # OR {THEME}/{THEME}.md for sub-pages
├── explorations/       # crystallized query answers
├── decisions/          # decision log with reasoning
└── comparisons/        # side-by-side analyses
```

## Page types

| type | location | when to use |
|---|---|---|
| `entity` | `entities/{NAME}/` | A discrete thing you track over time |
| `concept` | `concepts/{NAME}.md` | A theme that connects multiple entities |
| `source-summary` | `sources/` | Compiled summary of one external source |
| `exploration` | `explorations/` | Crystallized answer to a research question |
| `decision` | `decisions/` | A decision you made, with reasoning |
| `comparison` | `comparisons/` | A vs B analysis |
| `meta` | root | `_schema.md`, `rules.md`, `false-beliefs.md` |

## Frontmatter standard

Every `.md` page (except `raw/`) must have YAML frontmatter:

```yaml
---
title: <human-readable title>
type: entity | concept | source-summary | exploration | decision | comparison | meta
domain: [investing | research | reading | writing | tech | life]  # one or more
sources: [raw/category/filename]   # only for source-summary
related: [[entity1]], [[concept1]] # wikilinks to related pages
created: YYYY-MM-DD
updated: YYYY-MM-DD
confidence: high | medium | low
---
```

**Entity pages** add these fields:
```yaml
aliases: [alt-name-1, alt-name-2]
tags: [tag1, tag2]
judgment: bullish | bearish | neutral | watching   # domain-specific, edit freely
```

## Wikilinks

Use double brackets: `[[entity-name]]`, `[[concept-name]]`. The LLM uses these for navigation. **Bidirectional**: if A links to B, B should link back to A. The cross-reference protocol (see `CLAUDE.md`) maintains this automatically.

For ambiguous names, use the file path: `[[entities/AAPL/profile|Apple]]`.

## The five layers, by rate of change

This is the most important design principle in the whole wiki:

> **Things that change at different speeds must be stored separately.**

| Layer | Rate of change | Examples |
|---|---|---|
| `raw/` | **Never** (after ingest) | PDFs, full articles, transcripts |
| `sources/` | **Rarely** (only when new evidence found) | structured summaries |
| `entities/` `concepts/` | **Weekly–monthly** | profiles, themes, frameworks |
| `explorations/` `decisions/` | **Per query** | crystallized answers |
| `rules.md` `false-beliefs.md` | **Quarterly** | hard-won lessons |

If you mix layers, fast-changing content drowns out slow-changing structure. Don't put your daily notes in the same folder as your validated rules.

## Ingest rules

When the user gives you a new source:

1. Move the original to `raw/<category>/` (immutable archive)
2. Create a `sources/<date>-<slug>.md` with structured summary
3. Identify entities & concepts mentioned; update or (with user confirmation) create those pages
4. Maintain bidirectional `[[wikilinks]]`
5. Append a row to `_log.md`
6. Run lint: `python scripts/wiki_index.py --lint`

Full protocol details in `CLAUDE.md`.

## Verifiable predictions (optional but powerful)

When a source contains specific, dated, falsifiable predictions, add this section to its source-summary:

```markdown
## Verifiable Predictions

| Prediction | Target date | Status | Verified date | Result |
|---|---|---|---|---|
| <claim> | YYYY-MM | pending | | |
```

States: `pending` → `confirmed` / `partially` / `denied`.

- `confirmed` 3+ times → suggest promoting to `rules.md`
- `denied` and reveals a bias → suggest adding to `false-beliefs.md`

The periodic verification job (run by user, weekly) processes overdue predictions.

## Concept synthesis (re-compilation)

Each `concept` page should have a `## Synthesis` section that summarizes all linked sources:

```markdown
## Synthesis

> Compiled from N sources, last updated YYYY-MM-DD

(3-5 sentences of core judgment, noting any disagreements between sources)

**Key data points**:
| Metric | Latest value | Source |
|---|---|---|

**Sources cited**:
- [[sources/<file>]] — relevance
```

**Trigger for re-compilation**: 3+ new sources cite this concept since last compilation.

## Domain customization

This template ships with `investing` as the example domain. To customize for another domain, edit the rename map below and apply via project-wide find-replace:

| Investing term | Research term | Reading term | Writing term |
|---|---|---|---|
| company | subject | author | reference |
| ticker | ID | ISBN | citekey |
| portfolio | reading list | shelf | bibliography |
| earnings | results | publication | release |
| catalyst | trigger | sequel | edition |

You can run all three domains in parallel — just create sibling top-level dirs (`wiki/companies/`, `wiki/books/`, `wiki/papers/`) and adjust the schema accordingly.

## Index generation

Run `python scripts/wiki_index.py` (no args) to regenerate `_index.json` and `overview.md`. Run `--lint` for health check, `--search "query"` for ad-hoc search, `--stats` for stats.
